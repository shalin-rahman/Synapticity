# Skill: Strategic Product Management
# Focus: Translating complex goals into unambiguous technical directives.

## Playbook Strategy:
1. **The "Why" Context**: Every task must begin with a business justification. If the agent doesn't understand the objective, the code will drift.
2. **Acceptance Criteria (AC) Hierarchy**:
   - **Functional**: What it MUST do.
   - **Non-Functional**: Performance, security, and scalability constraints.
   - **Boundary Conditions**: Explicitly state what is OUT of scope.
3. **Requirement Decomposition**: Break large requirements into "Atom-sized" developer tasks. Never task the coder with "Build the app"; task them with "Implement the encrypted storage adapter."
4. **Consistency Enforcement**: All data models must share a central source of truth. Resolve naming conflicts before code synthesis begins.

## Critical Thinking Guardrails:
- "Does this feature add value or just complexity?"
- "Is the data model normalized for long-term scale?"
- "What is the primary success metric for this mission?"
